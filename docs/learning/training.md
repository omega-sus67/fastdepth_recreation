# Training and fine-tuning

**Status: controlled exploratory training and resume checks run; a reliable multi-scene experiment remains pending.** Training changes model weights using gradients from an objective function. For supervised depth estimation, each RGB image is paired with a ground-truth map; a masked loss should use only valid target pixels. The optimizer updates parameters, while a learning-rate schedule controls step sizes. A checkpoint must save model weights, optimizer and scheduler state, epoch/step and random-number-generator state so interrupted runs can resume reproducibly.

Fine-tuning begins from existing weights and updates them on training data, often after a structural change such as pruning. A separate tuning set selects model and hyperparameters. The final evaluation set must not be used to choose candidates. Before a long run we must verify forward/backward passes, finite gradients, checkpoint restoration and the effect of batch size on the RTX 3060's 6 GB memory.

A tiny scene-grouped training/tuning subset has now been prepared; final evaluation scene identities remain unknown. Do not interpret the community checkpoint's stored metrics as a training run performed by this project. A future comparison must record loss, optimizer, learning rate, number of steps, seeds, augmentations, data identifiers, checkpoint hashes and compute budget; fine-tuned and non-fine-tuned candidates need comparable evaluation.

## Preliminary smoke test — 13 November

A bounded download of the first training shard timed out after reading about 49 MB and saving 16 files from one scene. We used the first 12 for training and four for a small tuning smoke check, verifying no exact file-hash matches with the local evaluation files. Both groups come from the same scene; scene/near-duplicate overlap with the official evaluation set is unknown. Thus the split is unsuitable for final model selection or a generalization claim.

The script `scripts/train_smoke.py` loads the converted model, computes mean absolute error over positive finite targets, calls `backward()`, and updates weights with Adam at learning rate 1e-5. Epoch 1 produced training MAE 1.01010 and tuning MAE 0.65698; resuming its saved model, optimizer and RNG state for epoch 2 produced training MAE 0.95651 and tuning MAE 0.91595. These are native unverified depth units, on tiny correlated samples. The tuning loss rose; this is not evidence of a successful improvement. Resume was exercised, but exact equivalence with uninterrupted training has not been tested. See `results/training/` for filenames, seeds, hashes and checkpoint artifacts.

## Scene-grouped controlled run — 13 November

After the first source timed out, `scripts/acquire_scene_subset.py` retrieved 16 samples from `basement_0001a` and 16 from `bedroom_0017` using pinned dataset-revision HTTP range requests. The former is used for training and the latter for tuning. The validation split has no exposed scene identifiers, so we checked decoded RGB/depth bytes for exact overlap and found none; this cannot rule out near-duplicates or shared scenes. The first acquisition attempt failed due to a relative-path handling bug and was preserved with `failure.json`; the corrected run wrote a new directory.

`configs/experiment_2026-11-13_lastdecoder12.json` records the comparison fixed before training. Both control and pruned candidate used exactly the same 16 training examples, a seeded shuffled order, Adam, learning rate 1e-5, batch size 1, one epoch and mean absolute error on finite positive depth targets. `scripts/train_scene.py` evaluates only the 16 separate tuning images before and after training; it does not select on the final 654 validation images. It saves model configuration/weights, optimizer, epoch, CPU/CUDA random states, shuffle-generator state, source/checkpoint hashes and data-manifest hash. A separate experiment compared two uninterrupted epochs with one epoch followed by resume: the resulting state dictionaries were bit-identical in this one run. This establishes that this tested resume path worked for this setting, not that every GPU training run is universally deterministic.

The pre-training original model was much better on the tiny tuning scene than after either fine-tuning run. In particular, its mean-image RMSE rose from 0.116838 to 0.400989 in native unverified units after one epoch. The cause is not established. Training uses batch size 1 and updates batch-normalization running statistics, so changed statistics are a plausible hypothesis; test it with a controlled frozen-BN experiment before asserting causality. With one scene per group and only 16 samples each, this is a debugging experiment, not generalization evidence.

## Batch-normalization mode ablation

Batch normalization has trainable scale/offset (gamma and beta) and non-trainable running mean/variance. In training mode it normalizes each batch using batch statistics and updates running statistics; in evaluation mode it uses stored running statistics and does not update them. This distinction matters with batch size one. We tested two matched runs starting from the same original checkpoint, same 16 training/16 tuning images, order, optimizer, learning rate, seed and one epoch. The only intended change was putting batch-normalization layers in evaluation mode while leaving their affine parameters trainable. This simultaneously changes the statistics used during forward/backward and prevents running-buffer updates; it is not a test of just buffer updates.

The original control's mean-image tuning RMSE was 0.116838 before training, 0.400989 after normal BN training, and 0.122571 after BN evaluation-mode training. Checkpoint comparison showed all 114 tracked BN buffers changed in normal training and none changed in BN evaluation-mode training; all 76 BN affine parameter tensors changed in the latter. This supports that BN mode matters **in this specific tiny experiment**, without proving a single isolated causal mechanism or generalizing to other scenes. The candidate trained with the same frozen-BN mode scored 0.294076, still worse than the unmodified baseline; the candidate's normal-mode result was 0.271104. The BN-mode ablation was motivated by the first tuning result, so it is exploratory and the tuning set has been inspected repeatedly. No final-evaluation improvement is claimed.

**Why consider BN here?** A batch of one can give noisy or shifted per-batch statistics, and updating running averages on a single room can move the model away from its original data distribution. But weight updates, the actual per-layer distributions and interactions with pruned channels can also matter. A fair follow-up needs more scenes, controls, multiple seeds and a held-out final protocol.

The subsequent first-decoder 160-channel candidate used the same frozen-BN settings as the matched control. Its mean-image tuning RMSE changed from 0.146354 to 0.170767 after one epoch, compared with 0.116838 to 0.122571 for the original control. Both its initial and trained scores were worse than the unmodified control. See the pruning note for the actual channel surgery. This comparison reuses a tiny, repeatedly inspected tuning scene and does not establish expected performance on new scenes.

## Recovery on the expanded scene-grouped subset — 14 November

After individual-channel ablation on 32 images from four training scenes, an expanded acquisition provided 128 training images from those four scenes and 64 tuning images from two other scenes. Before viewing tuning outcomes, we recorded the data amendment in `configs/experiment_2026-11-14_expanded_recovery.json`. Each original or pruned model trained for one epoch using identical sample order (seed 42), batch size 1, Adam at 1e-5, finite-positive-target MAE and BN evaluation mode; BN affine parameters still train. There is no scheduler or augmentation in this run. The 192/184/176 numbers denote retained channels of the original 200, using the same individual-channel ranking; each starts from the original, not from the preceding candidate.

| Model | Mean per-image tuning RMSE before training | After training |
| --- | ---: | ---: |
| Unpruned control | 0.428998 | 0.454392 |
| 192 channels | 0.573695 | 0.475736 |
| 184 channels | 0.711172 | 0.528955 |
| 176 channels | 0.909395 | 0.587736 |

Depth values are in the mirror's native, not independently confirmed, units. Each candidate improved after training relative to its own starting point, but all remained worse than the original unmodified model; the matched control also worsened after training. The 192-channel result is worse than the unmodified control but is better than its own pre-training state and close to the fine-tuned control. This does not isolate a causal mechanism, establish generalization from six scenes, or demonstrate a speedup. The original 32 scoring images are included in the 128-image training set; all candidates share the same tuning data, which has now been inspected. Records are `results/training/2026-11-14-expanded-{control,192,184,176}/summary.json`.

Run a candidate, for example, with `bash scripts/python.sh scripts/train_scene.py --checkpoint checkpoints/candidates/2026-11-14-ablation-192/candidate.pth --manifest data/nyu_depth_v2/multiscene_2026-11-14-expanded/manifest.json --overlap-report results/data/2026-11-14-expanded-overlap.json --output <new-directory> --freeze-bn`. The output includes before/after tuning metrics, optimizer and RNG state, and checkpoint/data hashes. One epoch was chosen as a fast initial recovery comparison; it was not proven optimal. More scenes, several seeds and controlled longer schedules remain necessary.

For a further matched run, the same 192-channel ablation checkpoint and expanded data were trained using normal BN mode instead of `--freeze-bn`, with all other intended settings unchanged. Mean-image tuning RMSE was 0.573695 before training in both runs; after one epoch it was 3.526827 in normal mode versus 0.475736 in frozen-BN mode. This large difference applies to a single run and 64 correlated images from two scenes; it does not isolate whether changing forward statistics, updating running buffers, or other interactions are responsible. BN affine parameters train in both modes. The simple-control configuration was written after earlier tuning inspection; see `results/training/2026-11-14-simple-controls.json` for artifact hashes and the [four-experiment walkthrough](four_experiments.md) for defense questions.
